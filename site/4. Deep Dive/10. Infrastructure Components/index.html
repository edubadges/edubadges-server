    Deep Dive: Infrastructure Components

    Overview

    This document covers the shared infrastructure components used across the Edubadges platform: caching, logging, notifications, theming, and monitoring.

    Components

    1. Caching Layer (cachemodel)

    Custom caching infrastructure built on pymemcache with automatic invalidation.

    CacheModel Base Class

    class CacheModel(models.Model):
    """Base model with automatic caching."""
    class Meta:
        abstract = True

    @classmethod
    def get_cache_key(cls, instance):
        """Generate cache key for an instance."""
        return f'{cls.__name__}_{instance.entity_id}'

    @classmethod
    def get_from_cache(cls, instance):
        """Get instance from cache."""
        key = cls.get_cache_key(instance)
        return memcached.get(key)

    @classmethod
    def invalidate_cache(cls, instance):
        """Invalidate cache for an instance."""
        key = cls.get_cache_key(instance)
        memcached.delete(key)

    @cached_method Decorator

    from cachemodel.decorators import cached_method

class Issuer(...):
    @cached_method(auto_publish=True)
    def cached_badgeclasses(self):
        """Cached method that invalidates on save/delete."""
        return list(self.badgeclasses.all())

    @cached_method(auto_publish=True)
    def cached_staff(self):
        return list(IssuerStaff.objects.filter(issuer=self))

    The decorator: 1. Caches the method result in Memcached 2. Automatically invalidates on model save/delete (when auto_publish=True) 3. Uses entity_id-based cache keys for consistency

    2. Structured Logging (badgrlog)

    Custom logging with JSON formatting and Loki integration.

    BadgrEventsLogger

    class BadgrEventsLogger:
    """Structured logger for Badgr events."""

    def __init__(self):
        self.handler = TimedRotatingFileHandler(
            filename='logs/badgr_events.log',
            when='H',
            interval=1,
        )
        self.handler.setFormatter(JSONFormatter())

    def log_event(self, event_type, user, details):
        """Log a structured event."""
        self.handler.emit({
            'event_type': event_type,
            'user_id': user.entity_id,
            'timestamp': timezone.now().isoformat(),
            'details': details,
        })

    3. Push Notifications (notifications)

    Firebase Cloud Messaging integration for push notifications.

    FCM Configuration

    # settings.py
firebase_admin.initialize_app()

from fcm_django.models import FCMDevice

def send_push_notification(user, title, body, data=None):
    """Send push notification to user's devices."""
    devices = FCMDevice.objects.filter(user=user, active=True)

    message = CloudMessage(
        title=title,
        body=body,
        data=data or {},
        registration_ids=devices.values_list('registration_id', flat=True),
    )
    message.send()

    Badge Notification Events

    from mobile_api.push_notifications import send_push_notification

# When a badge is awarded
def on_badge_awarded(badgeinstance):
    send_push_notification(
        user=badgeinstance.user,
        title='🎉 Badge Awarded!',
        body=f'You received {badgeinstance.badgeclass.name}',
        data={
            'badge_instance_id': badgeinstance.entity_id,
            'badge_class_id': badgeinstance.badgeclass.entity_id,
        },
    )

    4. Theming (theming)

    Per-subdomain theming for white-label deployments.

    Theme Model

    class Theme(models.Model):
    """Per-subdomain theme configuration."""
    domain = models.CharField(max_length=255, unique=True)
    logo = models.ImageField(upload_to='uploads/themes')
    welcome_message = models.TextField(blank=True)
    terms_template = models.CharField(max_length=255, blank=True)
    custom_css = models.TextField(blank=True)

    Theme Middleware

    class ThemeMiddleware:
    """Load theme based on request host."""
    def process_request(self, request):
        domain = request.get_host().split(':')[0]
        try:
            theme = Theme.objects.get(domain=domain)
            request.theme = theme
        except Theme.DoesNotExist:
            request.theme = None

urlpatterns = [
    path('', HealthCheckView.as_view(), name='health_check'),
]

# health/views.py
class HealthCheckView(APIView):
    def get(self, request):
        checks = {
            'database': self.check_database(),
            'memcached': self.check_memcached(),
            'celery': self.check_celery(),
        }

        healthy = all(checks.values())
        status = 200 if healthy else 503

        return Response(checks, status=status)

    def check_database(self):
        try:
            BadgeUser.objects.count()
            return True
        except Exception:
            return False

    7. Exception Handling (mainsite)

    class ExceptionHandlerMiddleware:
    """Catch unhandled exceptions and return structured JSON."""
    def process_exception(self, request, exception):
        logger.error(f'Unhandled exception: {exception}', exc_info=True)

        return JsonResponse({
            'error': {
                'type': type(exception).__name__,
                'message': str(exception),
                'code': getattr(exception, 'code', 500),
            }
        }, status=500)

    LOKI_API_URL Loki logging URL http://localhost
    FIREBASE_JSON_FILE Firebase service account ./secrets/serviceaccount.json
    DOMAIN Application domain 0.0.0.0:8000
    DEFAULT_DOMAIN Default domain for URLs http://0.0.0.0:8000

    Potential Improvements

    1. Cache Warming: No cache warming strategy. Consider pre-warming frequently accessed caches on deployment.

    2. Structured Log Aggregation: Loki integration is configured but log query dashboards are not documented.

    3. Notification Preferences: No user-level notification preferences (email vs push). Users receive all badge notifications.

    4. Health Check Granularity: Health check only verifies database connectivity. Consider checking all dependencies (Memcached, Firebase, etc.) with individual status reporting.

    5. Rate Limiting: No API rate limiting. Consider adding throttling per user/IP for the public API.
