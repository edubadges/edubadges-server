    Project Overview

    What is Edubadges Server?

    Edubadges Server is a Python/Django REST API backend for issuing and managing digital credentials in educational contexts. It follows the Open Badges specification and serves as the backend for the Edubadges platform — a digital badge management system for universities, schools, and educational organizations across the Netherlands and beyond.

    The project originated from Badgr, developed by Concentric Sky starting in 2015 as an open-source reference implementation of the Open Badges Specification.

    Core Purpose

    Edubadges enables educational institutions to: - Create, issue, and manage digital badges following the Open Badges standard - Support micro-credentials — certification units smaller than a full diploma - Integrate with learning management systems via LTI 1.3 - Provide multi-provider SSO (eduID, SURFConext) for Dutch higher education - Issue verifiable credentials following the W3C Open Badges 3 specification

    Target Users

    Role Description
    Educational Institutions Universities and schools managing badge programs
    Students & Learners Recipients of badges (badge earners)
    Instructors & Administrators Creators and issuers of badges
    HR Departments Organizations recognizing skills and achievements

    Key Features

    • Badge Issuance: Full badge lifecycle management — create, issue, revoke, and verify digital badges
    • Badge Management: Comprehensive tools for issuers to manage their badge classes and assertions
    • User Management: Support for badge earners, issuers, and institutional administrators with role-based access control
    • LTI Integration: LTI 1.3 deep linking for learning management system integration (Canvas, etc.)
    • Multi-Provider SSO: eduID and SURFConext authentication for Dutch higher education
    • Micro-credentials: Support for smaller certification units beyond full diplomas
    • Verifiable Credentials: Open Badges 3 (W3C) integration with blockchain timestamping
    • Direct Awards: Bulk badge issuance via SIS integration with scheduled awards
    • Public Verification: JSON-LD endpoints for Open Badges spec compliance and badge verification
    • Mobile API: Dedicated endpoints for the mobile companion app
    • Analytics: Insights and query endpoints for badge program analytics
    • Institutional Hierarchy: Institution → Faculty → Issuer organizational structure with cascading permissions

    Getting Started

    Prerequisites

    • Python 3.12
    • MySQL 8.x
    • Cairo (for SVG image processing)
    • Git (for submodules)

    Local Setup

    # Clone and initialize submodules
git clone https://github.com/edubadges/edubadges-server.git
cd edubadges-server
git submodule update --init

# Create virtual environment
python3.12 -m venv .venv
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
pip install -r requirements-dev.txt

# Configure environment
cp env_vars.sh.example env_vars.sh
# Edit env_vars.sh with your credentials
source env_vars.sh

# Set up database
./manage.py migrate

# Seed database with test data
./manage.py seed -c

    Run Development Server

    ./manage.py runserver

    Docker Setup

    # Set environment variables
export BADGR_DB_PASSWORD=your-password
export EDU_ID_SECRET=your-secret
export SURF_CONEXT_SECRET=your-secret
export OIDC_RS_SECRET=your-secret

# Run with Docker Compose
docker compose up

    Access Points

    • API Docs (Swagger): http://localhost:8000/api/schema/swagger-ui/
    • API Docs (ReDoc): http://localhost:8000/api/schema/redoc/
    • Staff Admin: http://localhost:8000/staff/
    • Superuser Login: http://localhost:8000/staff/superlogin
    • Health Check: http://localhost:8000/health

    Architecture Summary

    The system follows a layered Django architecture with 30+ applications organized into functional domains:

    1. Core Infrastructure — mainsite, badgeuser, basic_models, cachemodel, entity
    2. Badge Domain — issuer, signing, endorsement, directaward, backpack
    3. Institutional Hierarchy — institution, staff
    4. Integration — lti13, lti_edu, badgrsocialauth, ob3
    5. API Layers — mobile_api, public, badge_connect, insights, queries
    6. Support — notifications, theming, badgrlog, health

    See 2. Architecture Overview.md for detailed architecture diagrams.
